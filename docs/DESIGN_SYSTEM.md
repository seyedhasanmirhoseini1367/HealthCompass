# Design system and frontend rules

Audit prompt 7 (UX-01 to UX-03, SEC-10). Applies to every template.

## Files

| File | What |
|---|---|
| `static/css/tokens.css` | Colours, type scale, spacing, radii, shadows, motion |
| `static/css/components.css` | Buttons, fields, cards, badges, tables, alerts, modal, toast, empty state, skeleton, page header, layout utilities, focus ring, reduced motion |
| `static/css/main.css` | Site layout; legacy variable names alias the tokens |
| `static/css/pages/*.css` | Page-specific rules, moved out of `<style>` blocks |
| `static/css/generated.css` | Former inline `style=""` attributes as classes (`.x-…`). Replace with tokens and components when a template is reworked; do not add to it by hand |
| `static/js/styles.js` | Applies `data-inline-style` through the CSSOM; defines `hcIcon()` |
| `static/js/app.js` | Account menu, dialog, toasts, sidebar, delegated `data-*` behaviour |
| `static/js/pages/*.js` | Page scripts, moved out of templates; server data comes from a `<script type="application/json">` block |
| `static/icons.svg` | Icon sprite, generated by `scripts/build_icon_sprite.py` from Font Awesome Free (CC BY 4.0) |

## Rules

* No `<style>` blocks, no `on*=""` handlers, no inline `<script>` except
  `type="application/json"` data. The Content-Security-Policy is enforcing
  (`script-src 'self'`), so inline script does not run.
* Behaviour is declared with data attributes handled by `app.js`:
  `data-on-click="fn" data-args='[...]'`, `data-href`, `data-confirm`,
  `data-submit-form`, `data-copy`, `data-autosubmit`, `data-click-target`.
* Icons: `{% icon 'name' %}` in templates (decorative by default; pass
  `label='…'` when the icon carries meaning), `hcIcon('name')` in scripts.
  Rebuild the sprite after using a new icon: `python scripts/build_icon_sprite.py`.
* `confirm()`/`alert()` are not used: `hcConfirm()` (dialog) and `hcToast()`.
* Never remove the focus outline; `:focus-visible` draws one ring everywhere.
* `apps/dashboard/test_design_system.py` enforces all of the above.

## Keyboard walk-through (expected behaviour; check in a browser)

1. **Tab** from the top of any page: the first stop is "Skip to content",
   which moves focus to `<main id="main">`.
2. Next: logo, notifications bell, the account button
   (`aria-haspopup="menu"`, `aria-expanded`). **Enter** opens the menu and focuses
   its first item; **Escape** closes it and returns focus to the button; a click
   outside closes it.
3. Sidebar links follow; the current page carries `aria-current="page"`.
4. Deleting a record opens a native `<dialog>`: focus moves to Cancel,
   **Tab** stays inside, **Escape** or Cancel closes it and focus returns to
   the Delete button that opened it.
5. Upload: the file field is a labelled drop zone; **Enter** opens the
   picker; the submit button shows a busy state.
6. Chat: type in the question box, **Enter** sends; the answer streams into a
   live region.

This walk-through has not been run in a browser as part of this change; the
Playwright journeys planned in audit prompt 9 automate it.
