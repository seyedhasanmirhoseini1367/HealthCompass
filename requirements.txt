# Direct dependencies, pinned to the versions verified by the test suite.
#
# Every version below is the one installed in the environment where the full
# suite passes (653 tests, keyless, SQLite — see docs/PROJECT_AUDIT_ROADMAP.md
# P0-4). They were NOT resolved fresh: resolving would pick newer releases than
# the tested set and change working behaviour, which is the opposite of what
# pinning is for. To move a version, change it here deliberately and re-run the
# suite.
#
# Why pinned here rather than in a constraints file: Railway builds with
# Nixpacks, which auto-detects this file and runs `pip install -r
# requirements.txt` at build time. A PIP_CONSTRAINT environment variable would
# fail *open* if it were ever unset — the build would succeed while installing
# unpinned versions, which is worse than no pinning because it looks solved.
#
# KNOWN LIMITATION — transitive dependencies are not locked. A full lock must be
# generated on the deploy platform (Linux/CPython 3.11); a `pip freeze` taken on
# a Windows development machine can omit platform-conditional packages and would
# be a false guarantee. Tracked as a follow-up in the roadmap.
